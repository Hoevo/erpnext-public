# ERPNext 17 新环境销售合同操作指南

版本：原生 Contract + contract_ops 0.7.0 开发版  
更新日期：2026-11-11  
适用对象：合同经办、业务跟进及财务人员

本指南直接在 **ERPNext 17 新环境**中使用，无需另开测试站点。按实际合同、发票、银行到账及财务规则操作；文中的金额只用于说明步骤，不作为实际录入依据。

建议先完成第 3～7 节的主流程，再按合同约定使用先款后票、合并开票及续签功能。

## 1. 登录新环境

- 打开管理员提供的 **ERPNext 17 新环境地址**，使用本人账号登录。
- 进入“合同与票款 → 销售合同”，确认能看到“新增销售合同”入口。
- 地址、账号及密码由管理员单独提供；本指南不固定本机地址或端口。
- 合同经办和财务人员按各自权限录入、提交及核对单据。

开始操作前，确认以下业务资料已建立：

| 项目 | 使用内容 |
|---|---|
| 公司 | 实际签约、开票及记账主体 |
| 客户 | 合同客户及实际付款方的正确业务身份 |
| 服务项目／物料 | 实际收费项目，例如场地租赁服务 |
| 币种 | 合同约定币种 |
| 应收科目 | 财务为该公司／客户配置的应收账户 |
| 收入或往来科目 | 按业务性质配置的收入、代收往来或其他适用科目 |
| 税费模板 | 该笔业务适用的税率与税额科目 |
| 银行账户 | 实际收到款项的银行账户及对应科目 |
| 成本中心／项目 | 对应小区、项目或核算部门 |

**先查已有记录，再决定是否新增。** 已迁移的合同、税票、应收和收款，优先打开原单核对、建立关联；不要把同一笔历史业务再录一遍。

## 2. 认识单据与记账时点

| 页面／单据 | 用途 | 提交是否记账 |
|---|---|---|
| 合同 Contract | 主体、正文、签署、期限、履约和销售票款规则 | 不记账 |
| 开票计划 | 约定按哪个期间、何时、开多少金额 | 不记账 |
| 税票登记 VAT Invoice Record | 登记外部已经开出的税票及合同期次份额 | 不记账 |
| 应收发票 Sales Invoice | 确认客户应收及相应会计分录 | **记账** |
| 收款单 Payment Entry | 记录实际到账并核销应收 | **记账** |
| 收款计划 | 跟进计划金额、到期日、已收及未收 | 不额外记账 |
| 续签周期 | 跟进到期、续签和办理记录 | 不记账 |

登记税票不会自动创建应收发票；保存计划也不代表已经开票或收到款项。不要为了“补凭证”再重复录入相同的 Journal Entry。

财务科目、税率和收入确认规则在财务基础资料及单据中设置，合同负责业务条件和关联。代小区收款、公司自营收入、跨期收入按各自财务口径处理，不能统一套用一个收入科目。

## 3. 打开已有合同，或新建销售合同

### 3.1 已有合同

1. 在“销售合同”列表按合同编号、客户或合同名称查找。
2. 核对原件、公司、客户、期限、金额、合同组、已有票款及计划。
3. 已迁移的合同继续使用原编号。原签署资料不完整时，按原件补充能够确认的信息，不为改变页面状态编造签署人或时间。
4. 如果本次业务已有对应期次，直接打开该期次，不再新建相同期间的计划。

### 3.2 新签合同

1. 点击 **“新增销售合同”**，底层单据为原生 `Contract`。
2. 检查“往来类型”为“客户／Customer”，勾选 **“启用销售票款管理”**。
3. 按原件填写以下内容：

| 字段 | 填写依据 |
|---|---|
| 往来单位名称 | 合同中的客户 |
| 合同名称、外部合同编号 | 原合同名称及编号，便于唯一定位 |
| 公司、币种 | 实际签约主体及合同币种 |
| 合同含税金额 | 已确认的合同金额；年参考价与全期总额要区分 |
| 开始日期、结束日期 | 合同原件约定的履行期限 |
| 票款顺序 | 按条款选择“先票后款”或“先款后票” |
| 合同正文／模板 | 原合同正文，或适用于该业务的合同模板 |
| 合同附件 | 上传原件及必要补充协议 |
| 合同组 | 同一来源协议组或需要共同跟进的合同组 |
| 续签设置 | 根据实际条款填写，详见第 10 节 |

4. 已签署的合同勾选“已签”，填写真实签署人及实际签署时间；未签署的保持实际状态。
5. 如需履约清单，填写真实履约事项、截止日和完成情况。
6. 保存，核对后提交，记录合同编号。

**应看到：**原生签署、正文／模板和履约区域保留；提交后的销售合同出现“新增开票计划”“登记税票”“新建应收发票”等按钮。

“已提交”是单据流程状态，“已签”是签署信息，两者含义不同。原生有效状态还会参考合同期限。

## 4. 建立开票计划

以下主流程适用于 **先票后款**。

1. 打开对应合同，先检查是否已有本期计划。
2. 未建立时，点击 **“新增开票计划”**。
3. 填写期次名称、计费开始／结束日期、计划开票日和本期完整含税金额。
4. 按合同选择收款到期规则：固定日期、开票后自然日／工作日、确认收票后自然日／工作日。
5. 填写间隔天数、固定日期或适用的工作日历，并在备注中保留条款依据。
6. 保存后回到合同，点击“刷新计划”。

例如：本期完整金额为1,000元，即使已经收到400元，也应保留本期1,000元的完整计划，并关联已有400元收款，不只建剩余600元的计划。

**应看到：**计划展示完整金额、期间、已开票和已收款。计划本身不生成会计分录。

条款为工作日时，必须维护覆盖起算日及到期日的工作日历。实际收票日未知时保留待确认，不用开票日、今天或预计日代替；预测日期不能直接用来认定合同逾期。

## 5. 创建或关联应收单，登记实际税票

### 5.1 应收发票

1. 先查是否已有该笔应收；已有的直接使用原单。
2. 确需新增时，在合同中点击 **“新建应收发票”**。
3. 检查公司、客户、币种、销售合同及本次计费期间。
4. 选择实际收费项目，填写数量、单价，选择适用税费模板。
5. 核对应收科目、项目明细中的收入／往来科目、成本中心或项目，以及含税总额、税额。
6. 按财务确认的日期填写记账日期、到期日。若手工指定记账日期，勾选原生的“编辑记账日期和时间／Edit Posting Date and Time”。
7. 保存并由有权限的人员提交，记录 `ACC-SINV-...` 编号。

**应看到：**新增应收及相应会计分录。若已有核销、预收抵扣等，未收余额应与实际业务一致。

应收确认时间由会计规则决定，不必机械地等同外部税票开具日；实际顺序按本笔业务处理。

### 5.2 外部税票登记

1. 查找该发票号码，确认尚未登记；已登记的打开原单核对关联。
2. 新登记时，优先从对应开票计划点击 **“登记本期开票”**。
3. 填写真实税票号码、实际开票日期、价税合计、税额及附件，保留票面原文。
4. 选择对应的已提交应收发票。若期次明细和表头都填写应收单，两者应一致。
5. 核对“关联期次及金额”：本次分配合计必须等于税票价税合计，累计不能超过期次可开金额。
6. 保存并提交，记录 `VAT-...` 编号。

**应看到：**对应期次已开金额增加；先票后款税票按期次生成收款计划，税票登记本身不会再生成一份收入分录。

如果暂时无法关联应收，税票及计划的缺失关联需要后续补齐，不能把“税票已登记”视为应收、收款全链路已经完成。

## 6. 登记真实到账并核销

### 6.1 先检查是否已经入账

按银行流水号、金额、日期和客户查找收款单。历史款已导入或已做过收款单时，使用已有单据进行核对／核销，不再新增同一笔银行到账。

### 6.2 新增一笔到账

1. 打开对应应收，从 **“创建／Create → Payment（付款／收款单）”** 进入；也可从“收款与核销”新建 `Payment Entry`。
2. 类型选择“收款／Receive”，往来类型为“客户／Customer”。
3. 核对公司、客户、币种、应收账户及实际到账银行账户。
4. 按银行凭据填写金额、流水／参考号、参考日期及银行实际到账日期；记账日期按财务规则填写。
5. 在参考单据明细中选择对应应收，填写本次实际核销金额。
6. 保存并由有权限的人员提交，记录收款单编号。

**金额示例，仅说明部分收款的变化：**

| 操作 | 本次核销 | 本期累计已收 | 本期未收 |
|---|---:|---:|---:|
| 本期应收1,000元，第一笔实际到账400元 | 400 | 400 | 600 |
| 第二笔实际到账600元 | 600 | 1,000 | 0 |

只有发生对应的真实到账才按该金额录入，不为完成示例而录两张收款单。

**应看到：**应收未收余额更新，关联收款计划及合同计划中的执行情况随核销更新。一笔款覆盖多个合同时，按各应收的实际份额分配，不能在每份合同下重复计入整笔金额。

## 7. 查看会计凭证

通过单据上的“查看会计分录／Accounting Ledger”入口，或在顶部搜索“总账／General Ledger”，按凭证类型和单据编号筛选。

对于已按财务规则确定为收入的普通应收业务，基本关系如下；具体科目以该笔业务配置为准：

| 来源 | 借方 | 贷方 |
|---|---|---|
| 提交应收发票 | 对应客户的应收科目 | 适用收入科目及税额科目 |
| 提交实际收款单 | 实际到账银行科目 | 对应客户的应收科目 |

代收公共收益、递延收入、预收等按其财务口径记账，不统一套用上表的收入科目。合同、计划和税票登记不会各自再记一份相同收入。

当前尚未完成自动向外部财务系统生成凭证并回写编号的功能。如需在外部系统做账，应核对科目映射、日期、金额及已有外部凭证，避免重复生成。

## 8. 先款后票

仅在实际合同约定先收款后开票时使用。已有计划的合同不直接切换票款顺序。

1. 打开票款顺序为“先款后票”的合同，检查是否已有对应收款期次。
2. 未建立时，点击“新增先款后票收款计划”，填写完整金额、计费期间、约定收款日及条款依据。
3. 根据条款选择“每笔到账”或“本期收齐”，填写到账后开票间隔、自然日／工作日及日历。
4. 实际到账后，从该期次点击“登记本期到账”，核对或录入相应收款单。
5. 填写 **“银行实际到账日期”**，并在“先款后票收款期次分配”中填写实际归属本期的金额。
6. 已有同合同应收时可关联相应核销；没有应收时，不虚构应收引用，先按适用预收规则处理。
7. 提交后检查自动生成的开票计划：金额、计划开票日和付款来源应与本次实际到账及起算方式一致。
8. 实际开出税票后，从对应生成计划登记，填写真实开票日及号码。

例如，约定到账后2个自然日开票时，计划日期为实际到账日加2天。这是跟进期限，不能当成已经发生的开票日期。

**应看到：**实际到账后生成开票义务；此类税票不会循环再生成一份先票后款收款计划。后续预收与应收核销继续使用原生财务流程，不再记一次相同银行到账。

## 9. 一张税票覆盖多个合同

1. 核对本次税票实际覆盖的合同与期次，保证公司、客户、币种一致。
2. 进入“税票登记”列表，点击 **“按客户合并开票”**。
3. 选择对应公司、客户、币种和实际开票日期，点击“加载可开票期次”。
4. 只勾选本次税票实际包含的期次，填写各期本次金额。
5. 点击“生成一张税票草稿”，核对逐合同、逐期份额及合计。
6. 填写真实税票号码、税额及原件，保存并提交。

**应看到：**一张税票保留各合同份额；跨合同时顶部单一合同字段可以为空。先款后票期次还应保存对应付款来源。一次实际税票只登记一次。

## 10. 续签与到期办理

1. 在合同“续签与到期管理”填写续签方式、负责人、通知期限、提醒提前量及条款原文／依据。
2. 提醒提前量例如 `30,7,1,0`，表示相对办理截止日前30、7、1天及当天提醒；不是相对今天计算。
3. 启用提醒并保存。已提交且配置完整的合同应建立续签周期。
4. 打开周期，点击 **“登记续签办理”**，按实际情况选择“洽谈中”“已签新合同”“已发出不续签通知”等。
5. 填写实际处理日期、说明和附件，保存后核对办理记录。

自动通知由每日调度任务执行，需要新环境的 scheduler、worker 和站点调度正常运行。保存配置不等于马上发通知；无通知时请管理员核对任务状态、负责人启用状态和权限。

“已签新合同”须关联已提交、同公司同客户、后继期间正确的新合同。“已确认按条款续期”只适用于自动续期，须实际进入下一周期，不能提前确认或代替签约。

## 11. 校验提示、取消与修订

操作中遇到以下提示，先核对依据和关联，不通过改金额、日期或数据库绕过校验：

| 提示类型 | 核对内容 |
|---|---|
| 税票表头金额与期次分配不一致 | 分配合计是否等于本票价税合计 |
| 累计开票超过计划 | 是否重复登记、是否选错期次、本期完整金额是否正确 |
| 公司／客户／币种不一致 | 合同、应收、税票、付款归属是否一致 |
| 先款后票缺实际到账日期 | 补充有凭据的银行实际到账日 |
| 分配超过实际到账或计划金额 | 核对本笔可分配金额与期次剩余额度 |
| 已有计划不能切换票款顺序 | 保留历史规则，按实际业务办理后续协议或修订 |
| 已有收款核销不能直接取消税票 | 先核实相关收款和核销，再按实际更正流程处理 |

取消或修订只用于真实业务更正，不为完成操作体验而撤销真实单据。应按关联提示处理，保留原因和原单号。先款后票收款已产生实际税票时，需要先处理相关税票，不能直接撤销资金来源。

不直接删除已提交凭证。红字、退款及其他会计调整应分别按财务流程处理，不能通过删除合同或税票登记代替。

## 12. 常见问题

| 情况 | 说明／处理 |
|---|---|
| 找不到新增销售合同入口 | 确认登录的是17新环境，检查账号权限和应用安装情况 |
| 提交合同后没有开票按钮 | 检查客户类型、销售票款开关和提交状态 |
| 税票登记后没有应收 | 税票登记不自动创建应收，查找已有应收或按财务规则新增 |
| 没有自动生成收款计划 | 先票后款需提交带期次分配的税票；只保存草稿或计划不会触发 |
| 收款已提交但应收仍未收齐 | 检查是否关联正确应收、核销金额是否正确、有无未分配预收款 |
| 工作日历缺失 | 配置有覆盖范围的日历，按真实条款计算，不改成自然日凑日期 |
| 历史合同显示未签 | 按原件核实后补充能够确认的签署资料，不补造信息 |
| 计划日期已过或早于开票 | 核对实际收票日、条款和来源；历史预测日期不等于已确认逾期 |
| 默认科目不符合业务 | 交财务完善公司、客户、项目及税费映射，再核对单据科目 |

## 13. 操作后核对与反馈

- [ ] 合同主体、客户、金额、期限及原件关联正确。
- [ ] 本期有完整计划，未重复新增已有期次。
- [ ] 税票号码、金额、税额、日期和逐期分配正确。
- [ ] 应收单关联正确，未重复确认收入或应收。
- [ ] 收款依据、实际银行账户、日期及核销份额正确。
- [ ] 收款计划与应收的已收、未收相互对应。
