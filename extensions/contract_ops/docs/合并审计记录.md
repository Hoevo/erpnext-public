# Contract Ops 0.7.0 合并审计

日期：2026-11-11。审计基线：Hoevo/erpnext 默认主分支 develop，ERPNext上游基线 `47fa497d75ca1dfe7d5af7ee11559b8399dd3136`。

## 范围

本次审查功能分支相对 develop 新增的合同扩展，包括 Contract hooks、旧合同迁移、单据权限、公开API、计划金额与核销规则、税票和付款关系、续签、来源导入、网页展示及Docker部署。没有修改原生 Contract / Contract Template 控制器，也未审计ERPNext全量上游模块。

## 发现与处理

| 风险 | 问题 | 处理 |
|---|---|---|
| 高 | 历史关系迁移接口未检查操作者和单据权限，直接修改已提交单据子表 | 限定管理员角色、POST及具体单据权限；补齐目标容量、主体币种、税票合同范围及配套收款计划校验 |
| 中 | 历史修复和回填接口可由一般写入用户调用；批量回填缺少目标计划写权限校验 | 统一限定管理员角色与POST，补齐计划权限和先款后票来源限制 |
| 中 | 先款后票税票经过收款计划修复可能补出循环计划 | 对实际到账生成的开票计划仅刷新汇总，不生成收款计划 |
| 中 | 新合同可通过直接构造字段伪造迁移来源 | 在服务器阻止普通新建设置旧编号、SHA256与来源快照 |
| 中 | 税票快捷关联应收路径没有校验主体币种一致性 | 校验公司、客户、币种，并检查合同组读取权限 |
| 中 | 应收提交后可改写合同与期间，使税票及收款计划关系失配 | 提交后更新执行服务器校验，有关联单据时拒绝改写合同与期间 |
| 中 | 合同组固定人民币显示、可能混加币种，退款方向未区分 | 返回实际币种，拒绝混合汇总，退款核销取反；移除“两年推算”的固定描述 |
| 中 | 常驻任务队列未持久化 | Redis队列启用AOF，数据写入独立OPENCLAW_DB_PATH目录 |
| 低 | 部分写入型验收入口没有业务站点保护 | 添加明确的隔离站点断言 |

## 检查证据

- `tools\check_extension.py` 检查UTF-8、Python语法和DocType元数据。
- `offline_tests` 的16项规则检查。
- `tools\run_suites.py` 在隔离站点执行8组共178项数据库回归，包括新增18项权限、来源伪造、主体币种、迁移容量、配套关系、先款后票修复及提交后应收关联保护检查。
- `test_contract_group.run_acceptance` 另行验证跨合同核销、未分配预收及取消，结束回滚。
- 业务新环境只进行只读数据核对、浏览器和API验证，不运行写入回归套件。运行日志、逐表指纹、网页截图和结果保存在Git忽略的本地证据目录。
- 17后台重启后，桌面及手机合同组页面、原生合同与实时连接通过；版本API显示0.7.0，4个历史写接口的GET请求均返回403。22张业务表核对中，只有被浏览器打开的合同 `_seen` 字段由空变为管理员已查看；还原该字段后原指纹完全一致，其余21张表逐行指纹一致。
- 后台doctor确认worker在线，队列配置确认appendonly为yes。隔离检查容器在任务结束后停止，业务端口8261保留。
- CI检查以本次提交的 Contract Ops extension checks 结果为准；上游全量ERPNext测试不包含在上述176项中。

## 已知边界

ERPNext基础仍是17开发版；财务配置和原始业务证据缺项须分别核实。D盘可用容量偏紧，因此本次复用既有镜像与只读源码挂载，不构建或拉取新镜像；合并代码不等于发布了新的镜像产物。部署时必须使用与所选代码版本一致的扩展源码。版本内容见 `..\CHANGELOG.md`。
